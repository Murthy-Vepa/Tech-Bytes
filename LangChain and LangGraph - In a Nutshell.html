    💡 What are LangChain and LangGraph?
    LangChain is an open-source Python/JS framework that provides a prebuilt agent architecture and 1000+ integrations for models, tools, and data sources — letting you build AI agents in under 10 lines of code.

    LangGraph is a low-level orchestration runtime for building stateful, long-running agents with durable execution, human-in-the-loop, and streaming — powering LangChain agents under the hood.

    Agent Middleware (Hooks)

    from langchain.agents import create_agent
from langchain_core.messages import trim_messages
from langchain_core.tools import tool

@tool
def search(query: str) -> str:
    """Search the web for information."""
    return f"Results for: {query}"

# pre_model_hook: runs before every LLM call — trim conversation to last 4k tokens
def trim_history(state: dict) -> dict:
    state["messages"] = trim_messages(
        state["messages"],
        strategy="last",
        max_tokens=4096,
        token_counter=len,
        include_system=True,
    )
    return state

agent = create_agent(
    model="anthropic:claude-sonnet-4-6",
    tools=[search],
    pre_model_hook=trim_history,
)

# post_model_hook: runs after every LLM response — audit / log
def log_step(state: dict) -> dict:
    last = state["messages"][-1]
    print(f"[Audit] Agent step: {last.content[:120]}")
    return state

agent_with_logging = create_agent(
    model="openai:gpt-4o",
    tools=[search],
    post_model_hook=log_step,
)

    The Runnable Protocol

    Every LangChain component implements the Runnable interface — so they all compose the same way:

    MethodSyncAsyncDescription
    Single callinvoke(input, config)ainvoke(input, config)Process one input, return one output
    Batchbatch(inputs, config)abatch(inputs, config)Process many inputs in parallel
    Streamstream(input, config)astream(input, config)Yield output chunks as they arrive
    Event stream—astream_events(input, version="v2")Yield every intermediate event (tool calls, LLM tokens, etc.)
    Configwith_config(config)—Bind run name, tags, metadata, callbacks
    Fallbackwith_fallbacks([...])—Try primary; use backup on exception
    Retrywith_retry(stop_after_attempt=3)—Auto-retry on transient errors

    Callbacks & Events

    from langchain_core.callbacks import BaseCallbackHandler
from langchain_openai import ChatOpenAI

class MyCallbackHandler(BaseCallbackHandler):
    def on_llm_start(self, serialized, prompts, **kwargs):
        print(f"LLM started with {len(prompts)} prompt(s)")

    def on_llm_end(self, response, **kwargs):
        text = response.generations[0][0].text
        print(f"LLM finished: {text[:80]}...")

    def on_tool_start(self, serialized, input_str, **kwargs):
        print(f"Tool '{serialized['name']}' called with: {input_str}")

    def on_tool_end(self, output, **kwargs):
        print(f"Tool returned: {output}")

    def on_chain_error(self, error, **kwargs):
        print(f"Chain error: {error}")

# Attach to a model (fires on every call)
model = ChatOpenAI(callbacks=[MyCallbackHandler()])

# Or per-invocation (scoped to one call)
model.invoke("Hello!", config={"callbacks": [MyCallbackHandler()]})

    Async Usage

    import asyncio
from langchain_openai import ChatOpenAI

async def main():
    llm = ChatOpenAI(model="gpt-4o-mini")

    # Single async call
    response = await llm.ainvoke("What is Python?")
    print(response.content)

    # Run multiple calls concurrently
    questions = ["What is AI?", "What is ML?", "What is DL?"]
    results = await asyncio.gather(*[llm.ainvoke(q) for q in questions])
    for r in results:
        print(r.content)

    # Async token streaming
    async for chunk in llm.astream("Tell me a story about a robot"):
        print(chunk.content, end="", flush=True)

asyncio.run(main())

    ⛓️ LangChain — LCEL & Chains

    LangChain Expression Language (LCEL) lets you compose Runnables using the | pipe operator — each component takes the previous output as its input.

    LCEL Basics — The Pipe Operator

from langchain_openai import ChatOpenAI

    Runnables

    RunnableDescriptionUsage
    RunnableSequenceRun components in order (via |)chain = a | b | c
    RunnableParallelRun components in parallel, merge results{"key1": chain1, "key2": chain2}
    RunnableLambdaWrap any Python function as a RunnableRunnableLambda(lambda x: x.upper())
    RunnablePassthroughPass the input unchanged (useful for passing context)RunnablePassthrough()
    RunnableBranchConditional routing based on inputRunnableBranch((condition, chain), default)
    RunnableWithFallbacksTry primary, fall back to alternatives on errorchain.with_fallbacks([backup])

    @chain Decorator — Compose with Functions

    from langchain_core.runnables import chain
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

@chain
def classify_then_answer(question: str) -> str:
    """Classify the question type, then use the best prompt for it."""
    llm = ChatOpenAI(model="gpt-4o-mini")

    # Step 1: classify
    category = (ChatPromptTemplate.from_template("Classify as 'fact', 'opinion', or 'task': {q}") | llm | StrOutputParser()).invoke({"q": question})

    # Step 2: use category-specific prompt
    templates = {
        "fact":    "Answer this factual question concisely: {q}",
        "opinion": "Give a balanced perspective on: {q}",
        "task":    "Provide step-by-step instructions for: {q}",
    }
    template = templates.get(category.strip().lower(), "Answer: {q}")
    return (ChatPromptTemplate.from_template(template) | llm | StrOutputParser()).invoke({"q": question})

# @chain makes any function a Runnable — pipe-able with | operator
result = classify_then_answer.invoke("How do I make pasta?")

    Tool Best Practices

    • ✅ Write clear, specific docstrings — the model uses these to decide when to call the tool
    • ✅ Use Pydantic schemas with Field(description=...) for all parameters
    • ✅ Return strings or JSON-serializable objects
    • ✅ Handle errors gracefully and return informative error messages
    • ✅ Keep tools focused — one tool per task
    • ❌ Avoid side effects in retrieval tools (save destructive ops for explicit tools)
    • ❌ Don't use more than ~20 tools per agent call (model performance degrades)

def safe_divide(numerator: float, denominator: float) -> float:

from typing import TypedDict, Literal

class State(TypedDict):
    messages: list
    next_action: str

def router(state: State) -> Literal["search", "calculate", "__end__"]:
    """Route based on the last message content."""
    last_msg = state["messages"][-1].content.lower()
    if "search" in last_msg:
        return "search"
    elif "calculate" in last_msg or any(c.isdigit() for c in last_msg):

graph.add_node("calculate", calculate_node)

)
graph.add_edge("search", "agent")
graph.add_edge("calculate", "agent")

    Human-in-the-loop (HITL) lets you pause an agent mid-execution for human review, approval, or correction. LangGraph implements this via interrupts — the graph pauses, saves state, and waits for human input before continuing.

    Dynamic Interrupt Inside a Node

    from langgraph.types import interrupt

def approval_node(state):
    """Node that pauses for human approval."""
    proposed_action = state["proposed_action"]
    
    # interrupt() pauses the graph and returns control to the caller
    # The value passed to interrupt() is returned to the human
    human_decision = interrupt({
        "question": "Do you approve this action?",
        "action": proposed_action,
    })
    
    # Execution resumes here after human provides input
    if human_decision.lower() == "yes":
        return {"approved": True}
    else:
        return {"approved": False, "reason": human_decision}

    for f in files:
        os.remove(f)
    return f"Deleted {len(files)} files"

def human_approval_node(state: MessagesState) -> Command:
    """Pause the graph and ask a human to approve or reject the last tool call."""
    last_msg = state["messages"][-1]

    if not last_msg.tool_calls:
        return Command(goto="agent")

    tool_call = last_msg.tool_calls[0]

    # interrupt() suspends execution and returns control to the caller
    decision = interrupt({
        "question": f"Approve '{tool_call['name']}' with args {tool_call['args']}?",
        "options": ["yes", "no"],
    })

    if decision == "yes":
        return Command(goto="tools")
    else:
        # Inject rejection message and loop back to agent
        return Command(
            goto="agent",
            update={"messages": [{"role": "tool", "content": "Action rejected by human."}]},
        )

graph = StateGraph(MessagesState)
graph.add_node("agent",    agent_fn)
graph.add_node("approval", human_approval_node)
graph.add_node("tools",    ToolNode([delete_files]))

graph.add_edge(START, "agent")
graph.add_edge("agent", "approval")   # Always go through approval
graph.add_edge("tools", "agent")
app = graph.compile(checkpointer=MemorySaver())

    Supervisor Pattern

    from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, MessagesState, START, END
from typing import Literal

members = ["researcher", "writer", "reviewer"]
options = members + ["FINISH"]

# Supervisor decides which worker to call next
supervisor_prompt = f"""You are a supervisor managing: {members}.
Given the conversation, decide who should act next.
Respond with one of: {options}"""

def supervisor_node(state: MessagesState):
    messages = [{"role": "system", "content": supervisor_prompt}] + state["messages"]
    response = ChatOpenAI(model="gpt-4o").invoke(messages)
    return {"messages": [response], "next": response.content.strip()}

def researcher_node(state: MessagesState):
    response = ChatOpenAI().invoke([
        {"role": "system", "content": "You are a researcher. Find facts."},
        *state["messages"]
    ])
    return {"messages": [response]}

def writer_node(state: MessagesState):
    response = ChatOpenAI().invoke([
        {"role": "system", "content": "You are a writer. Draft content."},
        *state["messages"]
    ])
    return {"messages": [response]}

def router(state) -> Literal["researcher", "writer", "reviewer", "__end__"]:
    next_node = state.get("next", "FINISH")
    return "__end__" if next_node == "FINISH" else next_node

graph = StateGraph(MessagesState)
graph.add_node("supervisor", supervisor_node)
graph.add_node("researcher", researcher_node)
graph.add_node("writer", writer_node)
graph.add_edge(START, "supervisor")
graph.add_conditional_edges("supervisor", router)
for member in members:
    graph.add_edge(member, "supervisor")

app = graph.compile()

from langchain_core.tools import tool

llm = ChatOpenAI(model="gpt-4o")

# Each agent is a compiled subgraph
def make_agent(name: str, expertise: str, tools: list = []):
    return create_react_agent(
        model=llm,
        tools=tools,
        prompt=f"You are {name}, an expert in {expertise}. When done, say HANDOFF_COMPLETE.",
    )

researcher = make_agent("Alex", "research and web search", tools=[search_tool])
writer     = make_agent("Blake", "writing and summarization")
reviewer   = make_agent("Casey", "quality review and critique")

# Each node runs its agent and decides if FINISH or handoff
def run_researcher(state: MessagesState):
    result = researcher.invoke(state)
    return {"messages": result["messages"]}

def run_writer(state: MessagesState):
    result = writer.invoke(state)
    return {"messages": result["messages"]}

def run_reviewer(state: MessagesState):
    result = reviewer.invoke(state)
    last = result["messages"][-1].content
    # Reviewer decides: done or ask writer to revise
    if "REVISE" in last.upper():
        return Command(goto="writer", update={"messages": result["messages"]})
    return Command(goto="__end__", update={"messages": result["messages"]})

graph = StateGraph(MessagesState)
graph.add_node("researcher", run_researcher)
graph.add_node("writer",     run_writer)
graph.add_node("reviewer",   run_reviewer)
graph.add_edge(START, "researcher")
graph.add_edge("researcher", "writer")
graph.add_edge("writer", "reviewer")
app = graph.compile()

    SSE / WebSocket Streaming Pattern

    from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import asyncio, json

app_web = FastAPI()
agent = your_compiled_langgraph  # Your compiled LangGraph

@app_web.post("/chat/stream")
async def chat_stream(body: dict):
    """Server-Sent Events endpoint — streams agent output to the browser."""
    user_message = body["message"]
    session_id   = body.get("session_id", "default")
    config = {"configurable": {"thread_id": session_id}}

    async def event_generator():
        async for msg, metadata in agent.astream(
            {"messages": [{"role": "user", "content": user_message}]},
            config=config,
            stream_mode="messages",
        ):
            if msg.content and not hasattr(msg, "tool_calls"):
                # SSE format: "data: ...\n\n"
                data = json.dumps({"token": msg.content, "done": False})
                yield f"data: {data}\n\n"
                await asyncio.sleep(0)  # Yield control to event loop

        yield f"data: {json.dumps({'done': True})}\n\n"

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",  # Disable nginx buffering
        },
    )

    🔗 LangChain Best Practices

    CategoryPractice
    ModelsUse with_structured_output() instead of output parsers for structured data — it uses native function calling
    ModelsSet temperature=0 for deterministic tasks (extraction, classification); higher for creative tasks
    ModelsUse with_fallbacks() to handle provider outages gracefully
    PromptsSeparate the system persona from the task instructions — first sentence = role, rest = task
    ToolsWrite clear, specific docstrings — they directly influence when the model calls the tool
    ToolsKeep tools focused; limit to <20 tools per agent call
    LCELUse .with_retry() on chains that call external APIs
    RAGChunk size 1000 / overlap 200 is a good starting point — tune based on your content
    RAGUse MMR retrieval to reduce redundant chunks in context
    AgentsAlways set max_steps to prevent runaway loops
    SecurityNever eval() untrusted input in tools — sanitize all code execution

    🕸️ LangGraph Best Practices

    CategoryPractice
    State DesignStart with MessagesState for chat agents; add custom fields only when needed
    State DesignUse explicit reducers (add_messages, operator.add) to avoid accidental state overwrite
    PersistenceAlways use a checkpointer in production — agents should be resumable on failures
    PersistenceUse PostgresSaver in production; MemorySaver only for tests
    NodesKeep nodes focused on a single responsibility — use the graph structure for orchestration
    EdgesUse tools_condition for tool-calling agents — don't reinvent routing logic
    StreamingUse stream_mode="messages" for chat UIs, "updates" for backend processing
    Multi-AgentUse sub-graphs for complex reusable agent logic — they can be independently tested
    HITLPrefer interrupt_before over dynamic interrupt() for predictable pause points
    DebuggingEnable LangSmith tracing (LANGSMITH_TRACING=true) — it visualizes every state transition

    🔒 Security

    • Never log or expose API keys — use environment variables
    • Validate and sanitize all tool inputs, especially code execution tools
    • Use interrupt_before for tools with destructive side effects (delete, send, pay)
    • Rate-limit agent calls to prevent abuse and runaway costs
    • Use content safety filters (Azure Content Safety, OpenAI moderation) for user-facing agents
    • Isolate agent tool permissions — apply principle of least privilege
