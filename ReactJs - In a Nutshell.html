    ⚛️ ReactJS - In a Nutshell

    intro overview ui-library

    What is React?

    React is an open-source JavaScript library for building user interfaces, maintained by Meta (Facebook) and a large community of developers. First released in 2013, it is now the world's most widely used front-end library, powering applications at Meta, Netflix, Airbnb, Atlassian, and thousands of other companies.

    React uses a declarative, component-based approach: you describe what the UI should look like for a given state, and React efficiently figures out the minimal set of DOM changes needed to make it happen.

    💡 Core Philosophy: React builds UIs as a tree of components. When data (state or props) changes, React efficiently re-renders only the affected subtree using its Virtual DOM and Fiber reconciler — not the entire page.

    Why React?

    ⚡ Declarative UI

    Describe what the UI should look like, not how to change it. React handles all DOM mutations automatically, making code predictable and easy to debug.

    🧩 Component-Based

    Build encapsulated components that manage their own state, then compose them to create complex UIs. Components are the fundamental unit of reuse and abstraction.

    🔄 Virtual DOM & Fiber

    React's Fiber reconciler maintains an in-memory tree, batches updates, and applies only the minimum required DOM changes. Concurrent Mode allows rendering to be interrupted for responsiveness.

    🌐 Learn Once, Write Anywhere

    React powers web apps, native mobile (React Native), desktop (Electron), static sites (Next.js SSG), and even VR (React 360). One mental model — many targets.

    📦 Rich Ecosystem

    The largest front-end ecosystem: meta-frameworks (Next.js, Remix), state management (Redux Toolkit, Zustand), server state (TanStack Query), UI libraries (shadcn/ui, MUI, Chakra).

    🔧 Great Developer Experience

    React DevTools for component inspection, Fast Refresh for instant feedback, TypeScript support built-in, and a massive community with solutions to almost every problem.

    JSX Basics

    jsx syntax transpilation

    What is JSX?

    JSX (JavaScript XML) is a syntax extension that lets you write HTML-like markup inside JavaScript. It is not valid JavaScript — it must be compiled by Babel or TypeScript to React.createElement() calls before running in the browser.

    JSX Compilation

    You write (JSX)
    function Greeting({ name }) {
  return (
    <div className="card">
      <h1>Hello, {name}!</h1>
    </div>
  );
}
    Babel compiles to (JS)
    function Greeting({ name }) {
  return React.createElement(
    'div',
    { className: 'card' },
    React.createElement('h1', null,
      'Hello, ', name, '!'
    )
  );
}

    JSX vs HTML — Key Differences

    HTMLJSXReason
    class="btn"className="btn"class is a reserved JS keyword
    for="email"htmlFor="email"for is a reserved JS keyword
    onclick="fn()"onClick={fn}camelCase event handlers, pass function reference
    style="color:red"style={{ color: 'red' }}Style is an object, not a string
    <br><br />All tags must be self-closing or explicitly closed
    <img src="..."><img src="..." />Self-closing tags require />
    tabindextabIndexAll HTML attributes become camelCase in JSX
    Multiple root elementsSingle root (or Fragment)JSX must return one root node

    JSX Rules

    • Return a single root element — wrap siblings in a <div> or <>…</> Fragment
    • All tags must be closed: <br />, <img />, <input />
    • Use camelCase for HTML attributes: onClick, className, tabIndex
    • JavaScript expressions go inside curly braces {}
    • Comments in JSX use {/* this is a comment */}
    • Boolean attributes: <input disabled /> = <input disabled={true} />

    Expressions in JSX

    function UserCard({ user, score, tags, isAdmin }) {
  return (
    <div>
      {/* Variables */}
      <h2>{user.name}</h2>

      {/* Ternary (conditional rendering) */}
      {isAdmin ? <span className="badge">Admin</span> : <span>User</span>}

      {/* Short-circuit (render only if true) */}
      {score > 90 && <span>🏆 Top Scorer</span>}

      {/* Dynamic styles */}
      <p style={{ color: score > 50 ? 'green' : 'red', fontWeight: 'bold' }}>
        Score: {score}
      </p>

      {/* Array rendering — always include a key! */}
      <ul>
        {tags.map(tag => (
          <li key={tag.id}>{tag.label}</li>
        ))}
      </ul>
    </div>
  );
}

    React.memo — Preventing Unnecessary Re-renders

    React.memo wraps a component so it only re-renders when its props actually change (shallow comparison).

    // Without memo: re-renders every time parent renders
function ExpensiveList({ items }: { items: Item[] }) {
  // Heavy computation here...
  return <ul>{items.map(i => <li key={i.id}>{i.name}</li>)}</ul>;
}

// With memo: only re-renders when items prop changes
const ExpensiveList = React.memo(function ExpensiveList({ items }: { items: Item[] }) {
  return <ul>{items.map(i => <li key={i.id}>{i.name}</li>)}</ul>;
});

// Custom comparison function (when shallow compare isn't enough)
const Chart = React.memo(({ data }) => <svg>{/* ... */}</svg>,
  (prevProps, nextProps) => prevProps.data.version === nextProps.data.version
);
    💡 Memo tip: Don't add React.memo everywhere preemptively. Profile first. Memo has overhead — it only pays off when (a) the component re-renders often and (b) the re-render is expensive. Always pair with useCallback for function props.

    What are Props?

    Props (properties) are read-only inputs passed from parent to child components. React enforces unidirectional data flow — data flows down the tree via props, events flow up via callbacks.

    Passing & Receiving Props

  const user = { id: 1, name: 'Alice', role: 'admin' };

      age={30}                  // number
      isActive={true}           // boolean
      role={user.role}          // variable
      tags={['react', 'ts']}    // array
      onEdit={(id) => console.log(id)}  // callback

}

    What is State?

    State is component-private data that, when changed, causes React to re-render the component and keep the UI in sync. Unlike props (passed in from outside), state is owned and managed by the component itself.

    ⚠️ Golden Rule: Never mutate state directly — always call the setter function. Direct mutation doesn't trigger a re-render because React uses reference equality to detect changes.

    useState — Basic Usage

    import { useState } from 'react';

function Counter() {

  return (
    <div>
      <p>Count: {count}</p>
      {/* Functional update — always use when new state depends on old */}
      <button onClick={() => setCount(prev => prev + 1)}>+</button>
      <button onClick={() => setCount(prev => prev - 1)}>−</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}

    useReducer — Complex State Logic

    Use useReducer instead of useState when state transitions are complex, or when multiple sub-values depend on each other.

function reducer(state: number, action: Action): number {
  switch (action.type) {
    case 'increment': return state + 1;
    case 'decrement': return state - 1;
    case 'reset':     return action.payload;
    default: throw new Error(`Unknown action: ${(action as any).type}`);
  }
}

    useEffect vs useLayoutEffect

    useEffect (default)
    • Runs after the browser paints
    • Non-blocking — does not delay visual update
    • Best for: fetching data, subscriptions, timers
    • Use this 95% of the time
    useLayoutEffect
    • Runs before the browser paints (synchronously)
    • Blocks paint until effect completes
    • Best for: reading DOM layout, preventing flash
    • Use when you need DOM measurements before render

  | { type: 'SET_STEP'; payload: number }
  | { type: 'RESET' };

function reducer(state: CounterState, action: CounterAction): CounterState {
  switch (action.type) {
    case 'INCREMENT': return { ...state, count: state.count + state.step };
    case 'DECREMENT': return { ...state, count: state.count - state.step };

  }
}

    function useLocalStorage<T>(key: string, initialValue: T): [T, (value: T) => void] {
  const [state, setState] = useState<T>(() => {
    try {
      const stored = localStorage.getItem(key);
      return stored !== null ? (JSON.parse(stored) as T) : initialValue;
    } catch {
      return initialValue;
    }
  });

  const setValue = useCallback((value: T) => {
    try {
      setState(value);
      localStorage.setItem(key, JSON.stringify(value));
    } catch (err) {
      console.error('useLocalStorage: failed to save', err);
    }
  }, [key]);

  return [state, setValue];
}

    useFetch — With AbortController

    interface FetchState<T> { data: T | null; loading: boolean; error: Error | null; }

function useFetch<T>(url: string): FetchState<T> {
  const [state, setState] = useState<FetchState<T>>({ data: null, loading: true, error: null });

  useEffect(() => {
    const controller = new AbortController();
    setState(prev => ({ ...prev, loading: true, error: null }));

    fetch(url, { signal: controller.signal })
      .then(res => { if (!res.ok) throw new Error(res.statusText); return res.json() as Promise<T>; })
      .then(data => setState({ data, loading: false, error: null }))
      .catch(err => { if (err.name !== 'AbortError') setState({ data: null, loading: false, error: err }); });

    return () => controller.abort();
  }, [url]);

  return state;
}

// Usage
const { data: users, loading, error } = useFetch<User[]>('/api/users');

    useDebounce — Delay Value Updates

    function useDebounce<T>(value: T, delay: number): T {
  const [debounced, setDebounced] = useState<T>(value);

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);

  return debounced;
}

// Usage — search only fires after 300ms of no typing
function SearchInput() {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query, 300);

  useEffect(() => {
    if (debouncedQuery) search(debouncedQuery); // only fires 300ms after last keystroke
  }, [debouncedQuery]);

  return <input value={query} onChange={e => setQuery(e.target.value)} placeholder="Search..." />;
}

    useOnClickOutside — Close Dropdowns & Modals

    function useOnClickOutside<T extends HTMLElement>(
  ref: React.RefObject<T>,
  handler: (event: MouseEvent | TouchEvent) => void
): void {
  useEffect(() => {
    const listener = (e: MouseEvent | TouchEvent) => {
      if (!ref.current || ref.current.contains(e.target as Node)) return;
      handler(e);
    };
    document.addEventListener('mousedown', listener);
    document.addEventListener('touchstart', listener);
    return () => {
      document.removeEventListener('mousedown', listener);
      document.removeEventListener('touchstart', listener);
    };
  }, [ref, handler]);
}

    Higher-Order Components (HOC)

    What is a HOC?

    A Higher-Order Component is a function that takes a component and returns a new enhanced component. HOCs implement cross-cutting concerns — auth guards, logging, loading states — without modifying the original component.

    // Signature: HOC takes a component, returns a new component
function withFeature<P extends object>(
  WrappedComponent: React.ComponentType<P>
): React.FC<P> {
  const WithFeature: React.FC<P> = (props) => {
    // inject behavior here...
    return <WrappedComponent {...props} />;
  };
  WithFeature.displayName = `withFeature(${WrappedComponent.displayName ?? WrappedComponent.name})`;
  return WithFeature;
}

    What is the Render Props Pattern?

    A component accepts a function as a prop (commonly render or children) and calls it to determine what to render. This decouples behavior (what data/state to track) from presentation (how to display it).

    Controlled List with Render Prop

    interface SelectableListProps<T> {
  items: T[];
  keyExtractor: (item: T) => string;
  children: (item: T, isSelected: boolean, toggle: () => void) => ReactNode;
}

function SelectableList<T>({ items, keyExtractor, children }: SelectableListProps<T>) {
  const [selected, setSelected] = useState<Set<string>>(new Set());

  const toggle = (key: string) =>
    setSelected(prev => {
      const next = new Set(prev);
      next.has(key) ? next.delete(key) : next.add(key);
      return next;
    });

  return (
    <ul>
      {items.map(item => {
        const key = keyExtractor(item);
        return (
          <li key={key}>
            {children(item, selected.has(key), () => toggle(key))}
          </li>
        );
      })}
    </ul>
  );
}

// Usage — total flexibility over how each item renders

>

      <span>{user.name}</span>
      <button onClick={toggle}>{isSelected ? 'Deselect' : 'Select'}</button>
    </div>
  )}
</SelectableList>

    What are Compound Components?

    Compound components are a group of components that work together, sharing implicit state through React Context. Think of native <select> + <option>, or <table> + <tr> + <td>. The consumer assembles them freely without prop-drilling.

function Accordion({ children, allowMultiple = false }: { children: ReactNode; allowMultiple?: boolean }) {
  const [openItems, setOpenItems] = useState<Set<string>>(new Set());

  const toggle = (id: string) =>
    setOpenItems(prev => {
      const next = new Set(prev);
      if (next.has(id)) {

        if (!allowMultiple) next.clear(); // close others

      return next;

  return (

      <div className="accordion">{children}</div>
    </AccordionCtx.Provider>
  );
}

        onClick={() => toggle(id)}
        className="accordion-header"
      >
        {title} <span>{isOpen ? '▲' : '▼'}</span>
      </button>
      {isOpen && <div id={`acc-${id}`} className="accordion-body">{children}</div>}

  );

  const [user, setUser] = useState<User | null>(null);

  const login = async (credentials: { email: string; password: string }) => {

    Splitting Context for Performance

    When a context holds both state and dispatch/actions, split them. Components that only call actions won't re-render when state changes.

    interface CartItem { id: string; name: string; price: number; qty: number; }
type CartAction =
  | { type: 'ADD'; item: CartItem }
  | { type: 'REMOVE'; id: string }
  | { type: 'CLEAR' };

const CartStateCtx   = createContext<CartItem[]>([]);
const CartDispatchCtx = createContext<Dispatch<CartAction>>(() => {});

function cartReducer(state: CartItem[], action: CartAction): CartItem[] {
  switch (action.type) {
    case 'ADD':    return [...state, action.item];
    case 'REMOVE': return state.filter(i => i.id !== action.id);
    case 'CLEAR':  return [];
    default:       return state;
  }
}

export function CartProvider({ children }: { children: ReactNode }) {
  const [cart, dispatch] = useReducer(cartReducer, []);
  return (
    <CartStateCtx.Provider value={cart}>
      <CartDispatchCtx.Provider value={dispatch}>
        {children}
      </CartDispatchCtx.Provider>
    </CartStateCtx.Provider>
  );
}

// Targeted hooks — each component subscribes only to what it needs
export const useCart     = () => useContext(CartStateCtx);
export const useCartDispatch = () => useContext(CartDispatchCtx);

// CartBadge re-renders only when cart items change
function CartBadge() {
  const cart = useCart();
  return <span>{cart.length}</span>;
}

// AddToCartButton NEVER re-renders due to cart state changes
function AddToCartButton({ item }: { item: CartItem }) {
  const dispatch = useCartDispatch();
  return <button onClick={() => dispatch({ type: 'ADD', item })}>Add</button>;
}

    TypeScript-Typed Store

    Zustand is a minimal, fast state management library. No boilerplate, no providers, no wrappers — just a hook.

    import { create } from 'zustand';
import { immer } from 'zustand/middleware/immer';

interface CartItem { id: string; name: string; price: number; qty: number; }

interface CartStore {
  items:      CartItem[];
  itemCount:  number;   // derived
  total:      number;   // derived
  addItem:    (item: Omit<CartItem, 'qty'>) => void;
  removeItem: (id: string) => void;
  updateQty:  (id: string, qty: number) => void;
  clearCart:  () => void;
}

export const useCartStore = create<CartStore>()(
  immer((set) => ({
    items:     [],
    itemCount: 0,
    total:     0,

    addItem: (product) =>
      set((state) => {
        const existing = state.items.find(i => i.id === product.id);
        if (existing) {
          existing.qty += 1;  // Immer allows direct mutation ✅
        } else {
          state.items.push({ ...product, qty: 1 });
        }
        state.itemCount = state.items.reduce((s, i) => s + i.qty, 0);
        state.total     = state.items.reduce((s, i) => s + i.price * i.qty, 0);
      }),

    removeItem: (id) =>
      set((state) => {
        state.items     = state.items.filter(i => i.id !== id);
        state.itemCount = state.items.reduce((s, i) => s + i.qty, 0);
        state.total     = state.items.reduce((s, i) => s + i.price * i.qty, 0);
      }),

    updateQty: (id, qty) =>
      set((state) => {
        const item = state.items.find(i => i.id === id);
        if (item) item.qty = Math.max(0, qty);
        state.items     = state.items.filter(i => i.qty > 0);
        state.itemCount = state.items.reduce((s, i) => s + i.qty, 0);
        state.total     = state.items.reduce((s, i) => s + i.price * i.qty, 0);
      }),

    clearCart: () => set({ items: [], itemCount: 0, total: 0 }),
  }))
);

async function apiFetch<T>(
  url: string,
  options?: RequestInit & { signal?: AbortSignal }
): Promise<T> {
  const res = await fetch(url, {
    headers: { 'Content-Type': 'application/json', ...options?.headers },
    ...options,
  });
  if (!res.ok) {
    const body = await res.text().catch(() => '');
    throw new Error(`HTTP ${res.status}: ${body}`);
  }
  return res.json() as Promise<T>;
}

    Request Retry with Exponential Backoff

    async function fetchWithRetry<T>(
  url: string,
  options: RequestInit = {},
  retries = 3,
  backoffMs = 300
): Promise<T> {
  for (let attempt = 0; attempt <= retries; attempt++) {
    try {
      return await apiFetch<T>(url, options);
    } catch (err) {
      const isLast = attempt === retries;
      const isNetworkErr = err instanceof TypeError;  // fetch network error
      if (isLast || !isNetworkErr) throw err;
      await new Promise(r => setTimeout(r, backoffMs * 2 ** attempt));
    }
  }
  throw new Error('Unreachable');
}

    Mutations with Optimistic Updates

    interface UpdateUserDto { id: number; name: string; }

function EditUser({ user }: { user: User }) {
  const queryClient = useQueryClient();

  const { mutate: updateUser, isPending } = useMutation<User, Error, UpdateUserDto>({
    mutationFn: (dto) => apiClient.put<User, UpdateUserDto>(`/users/${dto.id}`, dto),

    // --- Optimistic update ---
    onMutate: async (dto) => {
      await queryClient.cancelQueries({ queryKey: userKeys.lists() });
      const previous = queryClient.getQueryData<User[]>(userKeys.lists());

      // Immediately reflect the change in the cache
      queryClient.setQueryData<User[]>(userKeys.lists(), (old = []) =>
        old.map(u => (u.id === dto.id ? { ...u, ...dto } : u))
      );
      return { previous };  // context for rollback
    },

    onError: (_err, _dto, context) => {
      // Rollback on failure
      if (context?.previous)
        queryClient.setQueryData(userKeys.lists(), context.previous);
    },

    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: userKeys.lists() });
    },
  });

  return (
    <button
      disabled={isPending}
      onClick={() => updateUser({ id: user.id, name: 'Updated Name' })}
    >
      {isPending ? 'Saving...' : 'Save'}
    </button>
  );
}

    useReducer for Complex Form State

    type FormAction<T> =
  | { type: 'SET_FIELD'; field: keyof T; value: string }
  | { type: 'SET_ERROR'; field: keyof T; message: string }
  | { type: 'RESET' };

interface FormState<T> {
  values: T;
  errors: Partial<Record<keyof T, string>>;
  isDirty: boolean;
}

function formReducer<T extends Record<string, string>>(
  state: FormState<T>,
  action: FormAction<T>
): FormState<T> {
  switch (action.type) {
    case 'SET_FIELD':
      return {
        ...state,
        values:  { ...state.values,  [action.field]: action.value },
        errors:  { ...state.errors,  [action.field]: undefined },
        isDirty: true,
      };
    case 'SET_ERROR':
      return { ...state, errors: { ...state.errors, [action.field]: action.message } };
    case 'RESET':
      return { values: state.values, errors: {}, isDirty: false };
    default:
      return state;
  }
}

    Error Boundaries

    error fallback

    Error Boundaries catch render-phase errors in child trees and show fallback UI. They must be class components — or use the react-error-boundary library which wraps this for you.

    react-error-boundary (Recommended)

    import { ErrorBoundary, useErrorBoundary } from 'react-error-boundary';

// Fallback receives the error and a reset function
function ErrorFallback({
  error,
  resetErrorBoundary,
}: {
  error:                Error;
  resetErrorBoundary:   () => void;
}) {
  return (
    <div role="alert" className="alert alert-danger">
      <h4>Something went wrong</h4>
      <pre className="text-danger small">{error.message}</pre>
      <button className="btn btn-danger btn-sm" onClick={resetErrorBoundary}>
        Try again
      </button>
    </div>
  );
}

// Granular boundaries — isolate failures to a widget, not the whole page
function DashboardPage() {
  return (
    <div className="row g-3">
      <div className="col-md-6">
        <ErrorBoundary FallbackComponent={ErrorFallback}
          onError={(err, info) => logger.error(err, info)}   // Sentry, etc.
        >
          <SalesChart />
        </ErrorBoundary>
      </div>
      <div className="col-md-6">
        <ErrorBoundary FallbackComponent={ErrorFallback}>
          <UserActivityFeed />
        </ErrorBoundary>
      </div>
    </div>

// Programmatic error throwing from deep inside a tree
function DataWidget() {
  const { showBoundary } = useErrorBoundary();
  useEffect(() => {
    fetchData().catch(showBoundary);  // propagates to nearest ErrorBoundary

    Class-Based Error Boundary (TypeScript)

    interface Props    { fallback?: ReactNode; children: ReactNode; }
interface State    { hasError: boolean; error: Error | null; }

class ErrorBoundaryClass extends React.Component<Props, State> {
  state: State = { hasError: false, error: null };

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, info: React.ErrorInfo) {
    console.error('[ErrorBoundary]', error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback ?? <p>Something went wrong.</p>;
    }
    return this.props.children;
  }
}
    📌 Error boundaries do not catch errors in: event handlers (use try/catch), async code (setTimeout, promises), server-side rendering, or errors in the boundary itself.

    Portals

    portal modal

    Portals render children into a DOM node outside the parent hierarchy — ideal for modals, tooltips, and toasts where CSS overflow/z-index would otherwise clip the content.

    Typed Modal Portal

    import { createPortal }     from 'react-dom';
import { useEffect, useRef } from 'react';

interface ModalProps {
  isOpen:    boolean;
  onClose:   () => void;
  title:     string;
  children:  ReactNode;
}

function Modal({ isOpen, onClose, title, children }: ModalProps) {
  const closeButtonRef = useRef<HTMLButtonElement>(null);

  // Focus the close button when opened (accessibility)
  useEffect(() => {
    if (isOpen) closeButtonRef.current?.focus();
  }, [isOpen]);

  // Dismiss on Escape key
  useEffect(() => {
    if (!isOpen) return;
    const handleKey = (e: KeyboardEvent) => { if (e.key === 'Escape') onClose(); };
    document.addEventListener('keydown', handleKey);
    return () => document.removeEventListener('keydown', handleKey);
  }, [isOpen, onClose]);

  if (!isOpen) return null;

  return createPortal(
    <div
      className="modal d-block" role="dialog"
      aria-modal="true" aria-labelledby="modal-title"
      style={{ backgroundColor: 'rgba(0,0,0,0.5)' }}
      onClick={onClose}                              // click backdrop to close
    >
      <div
        className="modal-dialog modal-dialog-centered"
        onClick={e => e.stopPropagation()}           // prevent backdrop close
      >
        <div className="modal-content">
          <div className="modal-header">
            <h5 className="modal-title" id="modal-title">{title}</h5>
            <button ref={closeButtonRef} className="btn-close" onClick={onClose}
              aria-label="Close" />
          </div>
          <div className="modal-body">{children}</div>
        </div>
      </div>
    </div>,
    document.getElementById('modal-root')!           // mount point in index.html
  );
}

    useImperativeHandle — Expose a Limited API

    // Expose only specific methods — not the raw DOM node
interface VideoPlayerHandle {
  play:  () => void;
  pause: () => void;
  seek:  (seconds: number) => void;

const VideoPlayer = forwardRef<VideoPlayerHandle, { src: string }>(
  function VideoPlayer({ src }, ref) {
    const videoRef = useRef<HTMLVideoElement>(null);

    useImperativeHandle(ref, () => ({
      play:  () => videoRef.current?.play(),
      pause: () => videoRef.current?.pause(),
      seek:  (s) => { if (videoRef.current) videoRef.current.currentTime = s; },
    }), []);  // empty deps — API shape never changes

    return <video ref={videoRef} src={src} controls />;
  }
);

    ✨ Best Practices

    Component Design Principles

    ✅ Single Responsibility

    Each component should do one thing. If it grows beyond ~200 lines, extract sub-components or custom hooks.

    ✅ Colocate State

    Keep state as close to where it’s used as possible. Lift it up only when sibling components need it. Avoid global state for local UI.

    ✅ Composition over Inheritance

    Use children and component composition. Avoid class inheritance. Build flexible APIs with compound component or render prop patterns.

    ✅ TypeScript Everywhere

    Type all props, state, API responses, and hook return values. Use z.infer from Zod schemas to share types. Avoid any; prefer unknown.

    Mutating state directlyNo re-render triggeredAlways return new objects/arrays via setState
    Array index as keyList reconciliation bugs on reorder/filterUse stable unique IDs
