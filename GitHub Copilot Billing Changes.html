    📣 The Big Change

    overview breaking change
    ⚡ Effective June 1, 2026
    GitHub is moving all Copilot plans from request-based (Premium Requests) billing to usage-based (GitHub AI Credits / token-based) billing. This is the most significant billing change since Copilot launched.

    Why Is This Changing?

    The old model charged per request, regardless of whether a request was a simple one-liner or a complex 50-file agentic refactor. That created two problems:

    • ❌ Unfair pricing — a 10-token chat message cost the same as a 100,000-token agent session
    • ❌ Hard limits — you hit your request cap and stopped, even if the task wasn't done
    • ❌ Model-blind — using a cheap lightweight model and an expensive frontier model both counted as "1 request"

    The new model aligns cost with actual compute consumption, rewarding developers who use Copilot efficiently.

    At a Glance

    🔴 Old Model — Premium Requests

    • Fixed monthly request quota (e.g. 300 requests/month)
    • 1 request = 1 unit, regardless of size
    • Overage at $0.04 / request
    • No distinction by model used
    • Simple to predict, but coarse-grained

    🟢 New Model — GitHub AI Credits (Tokens)

    • Monthly AI Credits allowance (pool)
    • 1 AI Credit = $0.01 USD
    • Cost reflects actual token usage
    • Model-sensitive — frontier models cost more
    • Code completions remain unlimited & free

    🔴 Old Model: Premium Requests

    deprecated June 2026 request-based

    Under the Premium Requests model, every Copilot chat interaction that used a premium (non-base) model consumed one "Premium Request" from your monthly allowance.

    How It Worked

    📌 Definition of a Premium Request
    Any Copilot Chat message, Copilot CLI command, agent mode step, or cloud agent task that used a model above the included "base" tier consumed exactly 1 Premium Request — no matter how long or complex.

    Problems With This Model

    🔀 No Size Distinction

    A quick "What is React?" question and a complex "Refactor my entire auth service across 20 files" agent session both consumed exactly 1 request each.

    🤔 Model-Blind

    Using GPT-5 mini (cheap) vs. Claude Opus 4.7 (expensive) cost you the same 1 request. There was no incentive to choose efficient models.

    🚫 Hard Cutoffs

    Hit your 300-request cap mid-task? Work stopped. You either paid $0.04 per extra request or waited for the next billing cycle.

    📊 Poor Org Visibility

    Organizations couldn't see which interactions consumed value. Every request looked the same in usage reports.

    🟢 New Model: GitHub AI Credits (Tokens)

    effective June 1, 2026 token-based

    Starting June 1, 2026, Copilot moves to GitHub AI Credits. You're now billed based on the actual tokens consumed by each interaction, converted to a credit amount where 1 AI Credit = $0.01 USD.

    Understanding Tokens

    📐 What is a Token?
    A token is roughly 4 characters of text (or ¾ of a word). "The quick brown fox" ≈ 4–5 tokens. Large language models process everything — your prompt, the codebase context, and the generated response — in tokens.

    Three Types of Tokens

    INPUT

    Input Tokens

    What you send to the model: your message, code context, system instructions, file contents included in the prompt.

    OUTPUT

    Output Tokens

    What the model generates: code suggestions, explanations, analysis. Output tokens are typically 3–8× more expensive than input tokens.

    CACHED

    Cached Tokens

    Context the model reuses from previous turns (conversation history). Significantly cheaper — typically 90% less than regular input tokens.

    How AI Credits Are Calculated

    Formula:
    AI Credits = (Input Tokens × Input Rate + Output Tokens × Output Rate + Cached Tokens × Cache Rate) ÷ 1,000,000

    Where rates are per 1 million tokens, in USD. 1 AI Credit = $0.01 USD.
    So 100 AI credits = $1.00 USD.

    What Is and Is NOT Billed

    💳 Billed in AI Credits

    • ✅ Copilot Chat (IDE, GitHub.com, Mobile)
    • ✅ Copilot CLI interactions
    • ✅ Copilot Cloud Agent sessions
    • ✅ Copilot Spaces
    • ✅ GitHub Spark
    • ✅ Third-party coding agents
    • ✅ Copilot Code Review (+ GitHub Actions minutes)

    🎁 Remains Unlimited (NOT Billed)

    • 🚀 Inline code completions
    • 🚀 Next Edit Suggestions
    • 🚀 Ghost-text autocomplete
    Key point: The bread-and-butter autocomplete that developers use all day remains completely free and unlimited for all paid plans.

    🏊 The Pool Model
    For Business and Enterprise, credits are pooled at the billing entity level, not siloed per user.

    Example: An enterprise with 100 Copilot Business seats gets a shared pool of 190,000 AI Credits / month.
    Power users can draw more when they need it, while lighter users offset that consumption — no wasted credits sitting unused in individual buckets.

    🔌 Impact of MCP Servers & Tool Calls on Token Usage

    ⚠️ MCP Servers are a Token Multiplier
    When Copilot calls a Model Context Protocol (MCP) server (GitHub, Azure, FileSystem, databases, etc.), the tool's output is injected into the model's context window as additional input tokens. A single user question can trigger a chain of tool calls, each adding hundreds or thousands of tokens to the running context — dramatically inflating your AI Credit consumption compared to a plain chat message.
    📡

    How an MCP Tool Call Works

    User prompt → Model decides to call a tool → Tool runs → Result injected as input tokens → Model generates answer using that data.

    📈

    What Gets Injected as Tokens

    • The tool's JSON schema (every request)
    • Tool call arguments
    • Full tool response payload
    • Prior tool calls in the same turn
    🔗

    Chained Calls Compound Cost

    Each tool call in a chain adds its output to the running context. By call #4, earlier results are still present as cached tokens, costing less — but the context window keeps growing.

    🔌 MCP Server Billing Rules of Thumb
    • Every MCP tool schema is injected as input tokens on every request in that session — even for tools you didn't call this turn
    • Tool response payload is fully injected as input tokens — large API responses = expensive
    • More MCP servers configured = more schema tokens overhead per request
    • Chained tool calls where results feed the next call accumulate rapidly
    • Prefer targeted MCP queries (specific filters, smaller payloads) over broad "get everything" tool calls
    • Use @workspace file indexing rather than FileSystem MCP bulk reads when possible

    1. AI Credits — for token consumption (model is auto-selected, not disclosed)
    2. GitHub Actions minutes — for agentic infrastructure on GitHub-hosted runners
    Self-hosted runners do NOT consume Actions minutes.

    💡 Cost Optimization Tips

    tips optimization
    🎯 Core Principle
    In the new model, cost directly reflects how much work the AI does. The key to managing costs is matching the right model to the right task and writing focused prompts.

    1. Choose the Right Model for the Task

    ✅ Use Lightweight Models For:

    • Simple questions and lookups
    • Code completions and short fixes
    • Generating boilerplate code
    • Quick explanations of a function
    • CLI command suggestions

    Recommended: GPT-5 mini, Gemini 3 Flash, Claude Haiku 4.5, Raptor mini

    ⚡ Use Frontier Models For:

    • Complex architectural decisions
    • Multi-file refactoring tasks
    • Security audit and review
    • Debugging hard-to-reproduce issues
    • Generating comprehensive test suites

    Recommended: Claude Opus 4.7, GPT-5.5, Gemini 3.1 Pro

    2. Write Focused Prompts

    ❌ Costly Prompt Style

    "Here is my entire codebase [paste 500 lines].
Can you find any issues?"

    Problem: Sends thousands of unnecessary tokens as input. Vague question generates a verbose, expensive response.

    ✅ Efficient Prompt Style

    "In the UserService.ts file, the login method
on line 45 throws a null reference when the
user is not found. How should I fix it?"

    Benefit: Precise context = fewer input tokens. Specific question = focused, shorter response.

    3. Use Context References, Not Pastes

    In VS Code, use #file:filename.ts, #selection, or @workspace references rather than pasting entire file contents into chat. Copilot intelligently retrieves only relevant context, reducing input token cost.

    4. Leverage Conversation History (Caching)

    • Continue in the same conversation thread rather than starting new chats — cached tokens from prior turns are significantly cheaper
    • Avoid clearing context unnecessarily in the middle of a task
    • For agentic tasks, let the agent complete the full task rather than restarting multiple times

    5. Use Auto Model Selection

    When you enable auto model selection, Copilot routes your prompt to the most cost-effective model capable of handling it well. This is often more economical than manually picking a frontier model for every interaction.

    6. Monitor Your Usage Dashboard

    • Check the Premium Request Analytics page to see projected spend under the new model
    • Download the CSV usage report which includes aic_quantity and aic_gross_amount columns
    • Use GitHub's billing preview tool to upload your CSV and get a side-by-side comparison of old vs. new costs

    7. Manage MCP Servers for Cost Efficiency

    🔌 MCP Servers are the biggest hidden cost driver
    Each configured MCP server adds its tool schemas to every request context, and tool call responses inject large payloads as input tokens. Without discipline, an agent with 5 MCP servers configured can cost 10–20× more per request than plain chat.

    ❌ Costly MCP Patterns

    • Configuring every available MCP server globally (all schemas loaded every time)
    • Using FileSystem MCP to read whole directories when you need 1 function
    • RAG retrieval with large chunk sizes (top-5 × 800 tokens = 4,000 injected tokens)
    • Fetching full API responses when only a few fields are needed
    • Repeated MCP calls that re-fetch the same data (no response caching)

    ✅ Efficient MCP Patterns

    • Only enable MCP servers relevant to the current task
    • Use specific file references (#file:path.ts) instead of directory reads
    • Tune RAG to return top-3 chunks with smaller chunk sizes (400–500 tokens)
    • Use MCP tools that support filtering: only request fields you need
    • Prefer @workspace semantic search over FileSystem MCP bulk reads
    • Combine related MCP queries into single tool calls where possible
    MCP Scenario Avg Extra Tokens Added Cost Impact Optimization
    1 MCP server configured ~120 tokens / request Low Only enable when needed
    5 MCP servers configured ~600 tokens / request (schemas) Medium (baseline overhead) Remove unused MCP servers
    Single tool call (small response) +300–600 tokens Medium Filter API response fields
    Tool call with large payload (e.g. full PR diff) +3,000–8,000 tokens High Request summary/partial diff
    RAG top-5 large chunks +3,500–5,000 tokens High Reduce to top-3, shrink chunk size
    Bulk file read (10+ files) +5,000–15,000 tokens Very High Use @workspace instead

    Use usage reports to find users consuming disproportionately high credits. Are they running heavy MCP sessions or using expensive frontier models for trivial tasks?

    🎓

    Train Teams

    Educate developers on model selection and MCP token cost. Simple tasks → lightweight models. Focused prompts → fewer injected tokens.

    ❓ Frequently Asked Questions

    faq

    General

    Q: Will code completions cost more?

    No. Inline code completions and next-edit suggestions remain completely free and unlimited for all paid plans. The billing change only affects AI-model-based features like Copilot Chat, agent mode, CLI, and cloud agent.

    Q: Do I need to do anything before June 1?

    If you're on a monthly plan, no action is required — you'll be automatically migrated. If you're on an annual plan, watch for GitHub's communications about your options before your renewal date.

    Q: Is my subscription price changing?

    No. The subscription price for all plans remains the same. Only the billing mechanism changes — from requests to credits.

    Q: What is a "Flex Allotment"?

    Flex credits are a variable additional monthly bonus on top of your base credits. They're designed to adapt as AI economics evolve — when model prices decrease or efficiency improves, GitHub can pass savings to you by adjusting the flex amount. Your base credits are always used first.

    Q: If I switch to a cheaper model, do I save credits?

    Absolutely. Within your included allowance, model choice affects how many credits you consume per interaction (and therefore how much headroom you have before hitting limits). When you exceed your allowance, cheaper models directly reduce overage charges.

    Q: Can I buy extra AI Credits?

    Yes. For paid plans, you can set a budget for additional usage and pay as you go at published per-credit rates. Note: this is not available if you subscribed via GitHub Mobile on iOS or Android.

    Business & Enterprise

    Q: How does the pooled credit model benefit us?

    With pooling, power users can draw more credits when they need them, while lighter users offset that consumption. You're no longer wasting credits locked in individual buckets for users who don't use Copilot heavily. It's more equitable and efficient at scale.

    Q: What happens when our org pool is exhausted?

    It depends on your policy configuration:

    • Additional usage allowed: Usage continues at published per-credit rates, billed to your org/enterprise.
    • Additional usage not allowed: Usage is blocked until the next billing cycle.

    Q: Can I prevent specific users from causing overage?

    Yes. Set a user-level budget slightly above their included amount. If they exhaust it, their Copilot access is halted — the org pool's capacity doesn't matter. This lets you protect the overall budget while giving power users more rope.

    Q: When should we upgrade from Business to Enterprise?

    Enterprise ($39/seat) includes 3,900 AI Credits vs. Business's 1,900. If your team regularly exhausts Business credits and incurs significant overages, Enterprise may actually be more cost-effective, plus you get enhanced features (org custom instructions, content exclusion, audit logs, etc.).

    Technical

    Q: Why is output priced higher than input?

    Generating tokens is computationally more expensive than reading them. The model has to run inference step-by-step for each output token (auto-regressive generation), while input tokens are processed in parallel. Output is typically 4–8× more expensive than input.

    Q: What is "cached" pricing and why does it matter?

    Cached tokens are parts of the context (like conversation history or large file contents) that the model has already processed in a prior turn and can reuse cheaply. Claude models charge a small fee to write something to cache, then a tiny fraction of the input rate to read from cache. For long agentic sessions, caching can reduce your bill by 70–90%.

    Q: How do I estimate my monthly spend before June 1?

    Use the billing preview tool at copilot-billing-preview.github.com. Download your usage CSV from the Premium Request Analytics page and upload it. The tool shows a side-by-side comparison of your current PRU spend and projected AIC spend.

    MCP Servers & Tool Calls

    Q: Why did my bill spike after I added MCP servers?

    Every MCP server you configure adds its tool schemas as input tokens on every request in that session — even for tools you didn't use in that particular turn. With 5 MCP servers configured, you might be paying for 500–700 extra input tokens per request purely as overhead. Additionally, when you do call an MCP tool, the full tool response payload is injected as input tokens. A single GitHub MCP call to fetch PR details can add 2,000–5,000 tokens.

    Q: Does Copilot bill for MCP tool calls separately from the chat message?

    No. Everything within a single agent turn — the user message, all tool schemas, all tool call arguments, all tool responses, and the final model output — is billed as a single combined token count. There is no separate per-tool-call charge. However, the total token consumption can be far higher than a simple chat, so the credit cost can be significantly higher.

    Q: My MCP server returns a large JSON payload. Can I reduce the cost?

    Yes. The best approaches are:

    • Filter on the server side — if your MCP tool supports query parameters, use them to return only the fields/records you need
    • Summarize before injecting — pre-process large payloads to extract key fields before they are injected as context
    • Reduce the retrieval scope — for RAG/vector search, lower the top-K parameter and reduce chunk size to inject fewer total tokens
    • Only invoke MCP when necessary — use @workspace semantic search for code files rather than FileSystem MCP bulk reads

    Q: Does using multiple MCP servers simultaneously multiply the cost?

    Yes, in two ways: (1) all configured MCP tool schemas are added as input tokens to every request, creating a baseline overhead proportional to the number and size of your MCP tool schemas; (2) if your agent calls multiple MCP tools in the same turn, all their responses accumulate in the context window. The token cost grows with each additional tool call. Limit configured MCP servers to those needed for the current task.

    Q: Are there MCP tool calls that are cheaper than others?

    Yes. MCP tools that return short, structured responses (e.g., a single boolean, a status code, a list of IDs) cost very little. Tools that return large bodies of text or code (e.g., full file contents, PR diffs, log tails, RAG document chunks) are the expensive ones. When building or selecting MCP tools, prefer APIs that return minimal, targeted payloads over broad "get everything" endpoints.

    Q: How does Copilot Code Review billing work with MCP context?

    Copilot Code Review is billed in two parts:

    1. AI Credits — for all token consumption (PR diff + system prompt + any MCP-injected context like linked issues, work items, related code). The model used is selected automatically by GitHub and not disclosed.
    2. GitHub Actions minutes — for the infrastructure running the agentic review pipeline on GitHub-hosted runners (self-hosted runners are free).

    Large PRs with many linked issues that are fetched via MCP significantly increase the AI Credit cost. Keep PRs focused and limit the "include linked issue context" options if cost is a concern.
