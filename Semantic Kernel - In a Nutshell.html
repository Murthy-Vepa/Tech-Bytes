    📖 Semantic Kernel — Overview

    intro overview ai sdk
    💡 What is Semantic Kernel?
    Semantic Kernel is a lightweight, open-source SDK from Microsoft that lets you build AI agents and integrate the latest AI models into your C#, Python, or Java codebase. It acts as the middleware between your application and AI services — orchestrating plugins, memory, filters, and prompt templates into production-grade AI solutions.

    What is Semantic Kernel?

    Semantic Kernel is Microsoft's open-source AI orchestration framework that connects large language models (LLMs) with your existing code and data. It acts as the middleware layer between your application and AI services such as Azure OpenAI, OpenAI, Ollama, and more.

    • Lightweight & modular — pick only the components you need via NuGet/pip
    • Enterprise-ready — telemetry, filters, responsible AI hooks built-in out of the box
    • Multi-language — C#, Python, and Java SDKs with v1.0+ stability guarantees
    • Future-proof — swap AI models (OpenAI → Anthropic → local) without rewriting app code
    • OpenAPI & MCP compatible — share plugins across teams, tools, and platforms
    • Agent-native — built-in Agent Framework for autonomous, multi-agent workflows

    📖 Kernel Overview

    kernel overview

    The Kernel is at the Center

    The Kernel acts as the central hub for all Semantic Kernel operations. It provides a single place to configure, monitor, and orchestrate your AI agents.

    When you invoke a prompt through the Kernel, it will:

    1. Select the best AI service to run the prompt (based on service selectors or serviceId)
    2. Build the prompt using the provided template engine
    3. Run the filter pipeline (pre-invoke hooks)
    4. Send the prompt to the AI service and await the response
    5. Run the post-invoke filter pipeline
    6. Parse and return the response to your application

    Two Types of Kernel Components

    ComponentDescriptionExamples
    ServicesAI services and infrastructure needed to run your appChat Completion, Embedding, Logging, HTTP Clients
    PluginsGroups of functions exposed to AI for performing workDatabase queries, API calls, calculations, file I/O

builder.AddAzureOpenAIChatCompletion(

// Add structured logging
builder.Services.AddLogging(c =>
    c.AddConsole().SetMinimumLevel(LogLevel.Information));

    🔗 Dependency Injection

    kernel di asp.net

    Using DI with ASP.NET Core

    Register Semantic Kernel as part of your application's service collection for proper ASP.NET Core integration:

    var builder = Host.CreateApplicationBuilder(args);

// Register AI service (singleton — expensive to create)
builder.Services.AddAzureOpenAIChatCompletion(
    deploymentName: "gpt-4o",
    endpoint: config["AzureOpenAI:Endpoint"]!,
    apiKey:   config["AzureOpenAI:Key"]!);

// Register plugins as singletons (with their own dependencies resolved via DI)
builder.Services.AddSingleton<LightsPlugin>();
builder.Services.AddSingleton<OrdersPlugin>();

// Compose the plugin collection from DI-resolved instances
builder.Services.AddSingleton<KernelPluginCollection>(sp => [
    KernelPluginFactory.CreateFromObject(sp.GetRequiredService<LightsPlugin>()),
    KernelPluginFactory.CreateFromObject(sp.GetRequiredService<OrdersPlugin>())
]);

// Register Kernel as TRANSIENT — lightweight, safe per-request
builder.Services.AddTransient(sp => {
    var plugins = sp.GetRequiredService<KernelPluginCollection>();
    return new Kernel(sp, plugins);
});

var app = builder.Build();
    💡 Why Transient for Kernel?
    The Kernel holds a mutable plugin collection. If registered as a singleton, one request's runtime plugin changes would leak into all others. Transient registration ensures each request gets a clean Kernel backed by the same shared services (AI clients, loggers).

    Injecting Kernel into Controllers / Services

    [ApiController]
[Route("api/[controller]")]
public class ChatController : ControllerBase

    🎛️ Events & Filters

    kernel filters middleware

    What Are Kernel Filters?

    Filters are middleware components that intercept and can modify the execution pipeline. They enable cross-cutting concerns like logging, telemetry, safety checks, PII redaction, and human-in-the-loop workflows — applied uniformly across all AI operations.

    Filter Types & Interfaces

    Filter TypeInterfaceTriggers OnUse For
    Function InvocationIFunctionInvocationFilterEvery native + prompt function callLogging, metrics, retry, caching
    Prompt RenderIPromptRenderFilterBefore prompt is finalized and sent to LLMPII redaction, prompt injection detection
    Auto Function InvocationIAutoFunctionInvocationFilterAI-requested function calls (auto-invoke loop)Human approval, rate limiting, security checks

    Filter Execution Pipeline

    sequenceDiagram participant App participant FuncFilter as Function Invocation Filter participant PromptFilter as Prompt Render Filter participant LLM participant AutoFilter as Auto Function Filter participant Plugin App->>FuncFilter: InvokePromptAsync() FuncFilter->>PromptFilter: (passes through) PromptFilter->>LLM: Rendered prompt LLM-->>AutoFilter: Requests function call AutoFilter->>Plugin: Execute plugin function Plugin-->>AutoFilter: Result AutoFilter-->>LLM: Function result LLM-->>FuncFilter: Final response FuncFilter-->>App: Return result

    Example: Logging Filter

    public class LoggingFilter : IFunctionInvocationFilter
{
    private readonly ILogger _logger;
    public LoggingFilter(ILogger<LoggingFilter> logger) => _logger = logger;

    public async Task OnFunctionInvocationAsync(
        FunctionInvocationContext context,
        Func<FunctionInvocationContext, Task> next)
    {
        var sw = Stopwatch.StartNew();
        _logger.LogInformation("Invoking {Plugin}.{Function}",
            context.Function.PluginName, context.Function.Name);
        try
        {
            await next(context); // ← call next filter or actual function
            _logger.LogInformation("Completed in {Ms}ms", sw.ElapsedMilliseconds);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Error in {Function}", context.Function.Name);
            throw;
        }
    }
}

// Register
builder.Services.AddSingleton<IFunctionInvocationFilter, LoggingFilter>();

    Example: Prompt Render Filter (PII + Injection Detection)

    public class PromptSafetyFilter : IPromptRenderFilter
{
    public async Task OnPromptRenderAsync(
        PromptRenderContext context,
        Func<PromptRenderContext, Task> next)
    {
        await next(context); // Build the rendered prompt first

        var rendered = context.RenderedPrompt ?? "";

        // Detect prompt injection keywords
        var injectionPatterns = new[] { "ignore previous", "disregard", "new instructions" };
        if (injectionPatterns.Any(p => rendered.Contains(p, StringComparison.OrdinalIgnoreCase)))
        {
            throw new InvalidOperationException("Potential prompt injection detected.");
        }

        // Redact SSNs before they reach the LLM
        context.RenderedPrompt = Regex.Replace(rendered,
            @"\b\d{3}-\d{2}-\d{4}\b", "[REDACTED-SSN]");
    }
}

builder.Services.AddSingleton<IPromptRenderFilter, PromptSafetyFilter>();

    Human-in-the-Loop with Auto Function Filter

    public class ApprovalFilter : IAutoFunctionInvocationFilter
{
    public async Task OnAutoFunctionInvocationAsync(
        AutoFunctionInvocationContext context,
        Func<AutoFunctionInvocationContext, Task> next)
    {
        // Only require approval for write/delete operations
        bool isDestructive = context.Function.Name.StartsWith("update_") ||
                             context.Function.Name.StartsWith("delete_") ||
                             context.Function.Name.StartsWith("send_");
        if (isDestructive)
        {
            Console.WriteLine($"⚠️  AI wants to call: {context.Function.PluginName}.{context.Function.Name}");
            Console.Write("   Approve? (y/n): ");
            if (Console.ReadLine()?.Trim().ToLower() != "y")
            {
                context.Terminate = true; // Cancel the entire auto-invoke loop
                return;
            }
        }
        await next(context);
    }
}

builder.Services.AddSingleton<IAutoFunctionInvocationFilter, ApprovalFilter>();
    ⚡ Filter Chaining
    Multiple filters of the same type are chained in registration order. Each filter must call await next(context) to pass control to the next filter in the pipeline. Omitting next() short-circuits all subsequent filters and the function itself.

    Function Metadata & Auto-Schema Generation

    Semantic Kernel automatically generates OpenAI-compatible JSON schemas from your function signatures:

    // Inspect what schemas are sent to the LLM
foreach (var plugin in kernel.Plugins)
{
    foreach (var function in plugin)
    {
        var schema = function.Metadata.Parameters
            .Select(p => new { p.Name, p.Description, p.ParameterType?.Name });
        Console.WriteLine($"{plugin.Name}.{function.Name}: {function.Description}");
    }
}
    🎯 Description Quality = AI Accuracy
    The AI uses [Description] attributes to decide which function to call. Vague descriptions lead to wrong function calls. Be specific: "Retrieves the current on/off state of a smart light by its numeric ID" is far better than "Gets a light".

    💻 Native Code Plugins

    plugins csharp

    Step 1: Define Your Plugin Class

    Annotate methods with [KernelFunction] and [Description] to expose them to the AI:

    using System.ComponentModel;
using Microsoft.SemanticKernel;

public class OrdersPlugin
{
    private readonly IOrderRepository _repo;
    public OrdersPlugin(IOrderRepository repo) => _repo = repo; // DI injected

    [KernelFunction("get_orders")]
    [Description("Retrieves all orders for a given customer ID")]
    public async Task<List<Order>> GetOrdersAsync(
        [Description("The unique customer identifier")] string customerId,
        [Description("Filter by status: 'pending', 'shipped', 'delivered'")] string? status = null)
    {
        return await _repo.GetByCustomerAsync(customerId, status);
    }

    [KernelFunction("cancel_order")]
    [Description("Cancels a pending order. Only works on orders with 'pending' status.")]
    public async Task<string> CancelOrderAsync(
        [Description("The order ID to cancel")] string orderId)
    {
        var success = await _repo.CancelAsync(orderId);
        return success ? $"Order {orderId} cancelled successfully."
                       : $"Cannot cancel order {orderId} — it may already be shipped.";
    }
}
    💡 Naming Convention
    Use snake_case for function and parameter names (e.g., get_orders, customer_id). Most LLMs are trained on Python-style function calling conventions and perform better with snake_case names.

    OpenAPI Plugin Authentication

    // Bearer token authentication
await kernel.ImportPluginFromOpenApiAsync(
    pluginName: "SecureApi",
    uri: new Uri("https://secure.api.com/openapi.json"),
    executionParameters: new OpenApiFunctionExecutionParameters
    {
        AuthCallback = async (request, cancellationToken) =>
        {
            var token = await tokenProvider.GetTokenAsync(cancellationToken);
            request.Headers.Authorization =
                new AuthenticationHeaderValue("Bearer", token);
        },
        EnableDynamicPayload = true  // Build request body dynamically
    });

    🔗 MCP Plugins

    plugins mcp

    What is MCP?

    The Model Context Protocol (MCP) is an open standard for connecting AI models to external tools and data sources. Semantic Kernel can act as both an MCP client (consuming tools) and an MCP server (exposing SK plugins).

    Consuming MCP Tools as SK Plugins (Client)

    dotnet add package Microsoft.SemanticKernel.MCP --prerelease
    using Microsoft.SemanticKernel.MCP;

// Connect to a local MCP server via stdio
var mcpClient = await McpClientFactory.CreateAsync(
    new McpServerConfig {
        Name = "filesystem",
        TransportType = TransportTypes.StdIo,
        TransportOptions = new Dictionary<string, string> {
            ["command"] = "npx",
            ["args"] = "-y @modelcontextprotocol/server-filesystem /workspace"
        }
    });

// Import all MCP tools as a named SK plugin
var fsPlugin = await mcpClient.AsKernelPluginAsync("FileSystem");
kernel.Plugins.Add(fsPlugin);

// Now the LLM can call filesystem tools automatically
var result = await kernel.InvokePromptAsync(
    "List all .cs files in the src/ directory");

    SSE Transport (Remote MCP Servers)

    // Connect to a remote MCP server via Server-Sent Events
var mcpClient = await McpClientFactory.CreateAsync(
    new McpServerConfig {
        Name = "github-tools",
        TransportType = TransportTypes.Sse,
        TransportOptions = new Dictionary<string, string> {
            ["url"] = "https://mcp.github.example.com/sse",
            ["headers:Authorization"] = $"Bearer {githubPat}"
        }
    });

    Exposing Your Kernel as an MCP Server

    // Make your SK plugins available to any MCP-compatible AI client
var mcpServer = kernel.AsMcpServer(new McpServerOptions {
    ServerInfo = new McpServerInfo {
        Name = "enterprise-tools",
        Version = "1.0.0"
    }
});

// Start the MCP server (stdio mode for local, HTTP for remote)
await mcpServer.RunAsync(StdioServerTransport.Instance);

    Caching Embeddings (Critical for Cost Optimization)

    // Cache embeddings — re-embedding the same text wastes money and adds latency
public class CachedEmbeddingService : ITextEmbeddingGenerationService
{
    private readonly ITextEmbeddingGenerationService _inner;
    private readonly IMemoryCache _cache;

    public async Task<IList<ReadOnlyMemory<float>>> GenerateEmbeddingsAsync(
        IList<string> data, Kernel? kernel = null,
        CancellationToken cancellationToken = default)
    {
        var results = new List<ReadOnlyMemory<float>>();
        var uncachedTexts = new List<(int idx, string text)>();

        for (int i = 0; i < data.Count; i++)
        {
            var key = $"emb:{data[i].GetHashCode()}";
            if (_cache.TryGetValue(key, out ReadOnlyMemory<float> cached))
                results.Add(cached);
            else
            {
                results.Add(default);
                uncachedTexts.Add((i, data[i]));
            }
        }
        if (uncachedTexts.Count > 0)
        {
            var newEmbeddings = await _inner.GenerateEmbeddingsAsync(
                uncachedTexts.Select(x => x.text).ToList(), kernel, cancellationToken);
            for (int j = 0; j < uncachedTexts.Count; j++)
            {
                var (idx, text) = uncachedTexts[j];
                var key = $"emb:{text.GetHashCode()}";
                _cache.Set(key, newEmbeddings[j], TimeSpan.FromHours(24));
                results[idx] = newEmbeddings[j];
            }
        }
        return results;
    }
}

    Cosine Similarity (Manual Comparison)

    // Calculate semantic similarity between two texts
float CosineSimilarity(ReadOnlyMemory<float> a, ReadOnlyMemory<float> b)
{
    var aSpan = a.Span; var bSpan = b.Span;
    float dot = 0, normA = 0, normB = 0;
    for (int i = 0; i < aSpan.Length; i++)
    {
        dot   += aSpan[i] * bSpan[i];
        normA += aSpan[i] * aSpan[i];
        normB += bSpan[i] * bSpan[i];
    }
    return dot / (MathF.Sqrt(normA) * MathF.Sqrt(normB));
}

    Retrieval Augmented Generation

    RAG grounds LLM responses in your own data by retrieving relevant documents at query time and including them in the prompt context:

    sequenceDiagram participant User participant App participant Chunker participant EmbeddingModel participant VectorDB participant LLM note over App,VectorDB: Ingestion Phase (done once) App->>Chunker: Raw documents Chunker-->>App: Text chunks App->>EmbeddingModel: Embed each chunk EmbeddingModel-->>App: Vectors App->>VectorDB: Store chunks + vectors note over App,LLM: Query Phase (real-time) User->>App: Ask question App->>EmbeddingModel: Embed question EmbeddingModel-->>App: Query vector App->>VectorDB: Top-K similarity search VectorDB-->>App: Relevant chunks App->>LLM: Prompt + question + chunks as context LLM-->>App: Grounded, factual answer App-->>User: Response

    Complete RAG Implementation

    // === INGESTION PHASE ===
// 1. Chunk documents (critical for quality)
string ChunkText(string text, int maxChunkSize = 500, int overlap = 50)
{
    var sentences = text.Split(". ");
    var chunks = new List<string>();
    var current = new StringBuilder();
    foreach (var sentence in sentences)
    {
        if (current.Length + sentence.Length > maxChunkSize && current.Length > 0)
        {
            chunks.Add(current.ToString().Trim());
            // Keep last ~overlap chars for context continuity
            current.Clear().Append(sentence.Length > overlap ? 
                sentence[^overlap..] : sentence);
        }
        else current.Append(sentence + ". ");
    }
    if (current.Length > 0) chunks.Add(current.ToString().Trim());
    return chunks; // Return as IEnumerable in real code
}

// 2. Ingest into vector store
var docs = Directory.GetFiles("./docs", "*.txt");
foreach (var file in docs)
{
    var content = await File.ReadAllTextAsync(file);
    var chunks = ChunkText(content);
    var embeddings = await embSvc.GenerateEmbeddingsAsync(chunks);
    for (int i = 0; i < chunks.Count; i++)
        await collection.UpsertAsync(new KbDocument {
            Id = Guid.NewGuid(), SourceFile = file,
            Content = chunks[i], Embedding = embeddings[i]
        });
}

// === QUERY PHASE ===
// 3. Answer queries with RAG
async Task<string> AskRagAsync(string question)
{
    var queryEmbed = await embSvc.GenerateEmbeddingAsync(question);
    var topDocs = await collection.SearchAsync(queryEmbed, top: 4).ToListAsync();

        $"[Source {i+1}]: {r.Record.Content}"));
    
    var prompt = $"""
        Answer the question using ONLY the provided sources.
        If the answer is not in the sources, say "I don't know."
        
        Sources:
        {context}
        
        Question: {question}
        """;
    
    var result = await kernel.InvokePromptAsync(prompt);
    return result.ToString();
}

    📖 Function Calling Overview

    function-calling overview

    How Function Calling Works

    1. Plugin functions are serialized as JSON schemas and sent to the LLM alongside the prompt
    2. The LLM reasons about the user's intent and selects which function(s) to call
    3. Semantic Kernel intercepts the tool_calls response from the model
    4. SK deserializes arguments and executes the function(s) — running filters as configured
    5. Function results are added to the chat history and sent back to the LLM
    6. The LLM uses results to form its final grounded response

    Function Calling Flow (Multi-Step)

    sequenceDiagram participant User participant SK as Semantic Kernel participant Filter as AutoInvoke Filter participant LLM participant Plugin User->>SK: "What are today's pending orders for customer 42?" SK->>LLM: Prompt + JSON schemas for get_orders, cancel_order LLM-->>SK: tool_call: get_orders(customerId="42", status="pending") SK->>Filter: OnAutoFunctionInvocationAsync (pre-invoke) Filter->>Plugin: get_orders("42", "pending") Plugin-->>Filter: [Order#789, Order#790] Filter-->>SK: Result (post-invoke) SK->>LLM: tool_result: [Order#789 $42.00, Order#790 $18.50] LLM-->>SK: "Customer 42 has 2 pending orders totalling $60.50." SK-->>User: "Customer 42 has 2 pending orders totalling $60.50."

    public class LoggingFilter : IAutoFunctionInvocationFilter
{
    private readonly ILogger _logger;
    public LoggingFilter(ILogger<LoggingFilter> logger) => _logger = logger;

    public async Task OnAutoFunctionInvocationAsync(
        AutoFunctionInvocationContext context, Func<AutoFunctionInvocationContext, Task> next)
    {
        var sw = Stopwatch.StartNew();
        _logger.LogInformation("Calling {Plugin}.{Function} with args: {@Args}",
            context.Function.PluginName, context.Function.Name,
            context.Arguments);
        try
        {
            await next(context);
            _logger.LogInformation("Completed {Function} in {Ms}ms. Result: {Result}",
                context.Function.Name, sw.ElapsedMilliseconds, context.Result);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Function {Function} failed", context.Function.Name);
            // Return a graceful error message to the LLM instead of throwing
            context.Result = new FunctionResult(context.Function,
                $"Error: {ex.Message}. Please try a different approach.");
        }
    }
}

    // Detects hate, self-harm, sexual, and violent content
public class ContentSafetyFilter : IPromptRenderFilter
{
    private readonly ContentSafetyClient _client;
    public ContentSafetyFilter(ContentSafetyClient client) => _client = client;

    public async Task OnPromptRenderAsync(
        PromptRenderContext context,
        Func<PromptRenderContext, Task> next)
    {
        await next(context);  // Let prompt render first

        // Check the rendered prompt before sending to LLM
        var analysis = await _client.AnalyzeTextAsync(
            new AnalyzeTextOptions(context.RenderedPrompt!)
            {
                Categories = [TextCategory.Hate, TextCategory.Violence,
                              TextCategory.SelfHarm, TextCategory.Sexual],
                OutputType = AnalyzeTextOutputType.FourSeverityLevels
            });

        foreach (var cat in analysis.Value.CategoriesAnalysis)
        {
            if (cat.Severity >= 2)  // 0=safe, 2=low, 4=medium, 6=high
            {
                throw new ContentSafetyException(
                    $"Content safety violation: {cat.Category} (severity {cat.Severity})");
            }
        }
    }
}

    PII Detection & Redaction Filter

    // Redact SSNs, credit card numbers, and email addresses from outputs
public class PiiRedactionFilter : IFunctionInvocationFilter
{
    // Regex patterns for common PII
    private static readonly Regex SsnPattern =
        new(@"\b\d{3}-\d{2}-\d{4}\b", RegexOptions.Compiled);
    private static readonly Regex CreditCardPattern =
        new(@"\b(?:\d{4}[-\s]?){3}\d{4}\b", RegexOptions.Compiled);
    private static readonly Regex EmailPattern =
        new(@"\b[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}\b",
            RegexOptions.Compiled | RegexOptions.IgnoreCase);

    public async Task OnFunctionInvocationAsync(
        FunctionInvocationContext context,
        Func<FunctionInvocationContext, Task> next)
    {
        await next(context);

        // Redact PII from function outputs
        if (context.Result?.GetValue<string>() is string output)
        {
            var redacted = SsnPattern.Replace(output, "[SSN]");
            redacted = CreditCardPattern.Replace(redacted, "[CARD]");
            redacted = EmailPattern.Replace(redacted, "[EMAIL]");
            context.Result = new FunctionResult(context.Function, redacted);
        }
    }
}

builder.Services.AddSingleton<IFunctionInvocationFilter, PiiRedactionFilter>();

    Rate Limiting Filter

    // Prevent abuse — limit function calls per user per minute
public class RateLimitFilter : IAutoFunctionInvocationFilter
{
    private readonly IMemoryCache _cache;
    private const int MaxCallsPerMinute = 30;

    public async Task OnAutoFunctionInvocationAsync(
        AutoFunctionInvocationContext context,
        Func<AutoFunctionInvocationContext, Task> next)
    {
        var userId = context.KernelArguments["userId"]?.ToString() ?? "anonymous";
        var key = $"rate:{userId}:{DateTime.UtcNow:yyyyMMddHHmm}";
        var count = _cache.GetOrCreate(key, e => {
            e.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(1);
            return 0;
        });

        if (count >= MaxCallsPerMinute)
        {
            context.Result = new FunctionResult(context.Function,
                "Rate limit exceeded. Please wait before making more requests.");
            context.Terminate = true;
            return;
        }
        _cache.Set(key, count + 1, TimeSpan.FromMinutes(1));
        await next(context);
    }
}

    Human-in-the-Loop Approval (Production Pattern)

    // Web API pattern — pause execution and await approval webhook
public class HumanApprovalFilter : IAutoFunctionInvocationFilter
{
    private readonly IApprovalService _approvals;
    private static readonly HashSet<string> RequiresApproval =
        ["cancel_order", "process_refund", "delete_account", "send_bulk_email"];

    public async Task OnAutoFunctionInvocationAsync(
        AutoFunctionInvocationContext context,
        Func<AutoFunctionInvocationContext, Task> next)
    {
        if (RequiresApproval.Contains(context.Function.Name))
        {
            var approved = await _approvals.RequestApprovalAsync(
                functionName: context.Function.Name,
                args: JsonSerializer.Serialize(context.Arguments),
                timeoutSeconds: 300);  // 5-minute approval window

            if (!approved)
            {
                context.Result = new FunctionResult(context.Function,
                    $"Action '{context.Function.Name}' was not approved.");
                context.Terminate = true;
                return;
            }
        }
        await next(context);
    }
}

    ⭐ Best Practices

    best-practices tips guidelines

    🧠 Kernel & Services

    Register Kernel as Transient
    Always register Kernel as transient in DI — it is lightweight and the mutable plugin collection makes singletons risky.
    • ✅ Reuse CosmosClient, HttpClient, and other heavy dependencies as singletons; inject them into plugins
    • ✅ Use Named AI Services (serviceId) to register multiple models for different tasks (e.g., "gpt-4o" for complex, "gpt-4o-mini" for simple)
    • ✅ Enable retry logic and configure preferred regions for high availability
    • ✅ Always configure a fallback AI service for resilience
    • ✅ Use kernel.Clone() to create per-request Kernel instances that share the same services but have isolated plugin collections
    • ❌ Don't create new Kernel instances in tight loops — use DI or Clone()

    🔌 Plugin Design

    • ✅ Use snake_case for function and parameter names (LLMs are trained on Python conventions)
    • ✅ Write clear, concise [Description] attributes — the AI relies on these for routing
    • ✅ Keep parameter count minimal — use primitive types where possible
    • ✅ Import only the plugins needed per scenario (OpenAI recommends < 20 tools per call)
    • ✅ Pass resource IDs to the LLM, not raw data — retrieve full data server-side
    • ✅ Provide return type description so the LLM can interpret results accurately
    • ❌ Don't put side-effectful functions (delete, send, pay) in retrieval plugins

    ⚡ Function Calling

    • ✅ Use FunctionChoiceBehavior.Auto() for agentic tasks; None() for pure generation
    • ✅ Set MaximumAutoInvokeAttempts ≤ 20 to prevent runaway loops
    • ✅ Use IAutoFunctionInvocationFilter for human-in-the-loop on write operations
    • ✅ Prefer direct InvokeAsync calls when the function to run is deterministically known
    • ✅ Always validate function arguments server-side — treat all LLM-supplied values as untrusted input
    • ❌ Don't rely on LLM function calling for security-critical authorization decisions

    🗄️ Memory & RAG

    • ✅ Use text-embedding-3-large (3072d) for production RAG; text-embedding-3-small (1536d) for cost-optimized
    • ✅ Chunk to ~512 tokens with ~10% overlap; preserve sentence boundaries
    • ✅ Use hybrid search (vector + keyword BM25) for best recall
    • ✅ Store source, date, author, and category metadata alongside embeddings for post-filtering
    • ✅ Re-rank top-K results (e.g., 20 → 5) with a cross-encoder for precision
    • ❌ Don't embed entire documents — chunk and embed individual passages

    🤖 Agents

    • ✅ Write clear, specific Instructions — include role, scope, constraints, and output format
    • ✅ Add a max-iteration termination strategy (e.g., < 15 rounds) to all AgentGroupChat instances
    • ✅ Give each agent in a multi-agent workflow a distinct, non-overlapping persona
    • ✅ Use persistent thread IDs for resumable agent sessions
    • ❌ Don't give a single agent > 15 plugins — specialize agents for focus

    📋 Prompt Engineering

    • ✅ Store production prompts in YAML files — enables versioning and iteration without code changes
    • ✅ Set explicit Temperature (0.2–0.4 for factual, 0.7–1.0 for creative tasks)
    • ✅ Use FunctionChoiceBehavior.Required() + output schema for reliable structured extraction
    • ✅ Use Handlebars when prompts need conditionals or loops; KPTL for simple variable injection
    • ✅ Always include explicit output format instructions for JSON extraction tasks
    • ❌ Don't hardcode production prompts in application code — use YAML and a prompt registry

    🛡️ Responsible AI & Security

    • ✅ Implement IPromptRenderFilter to detect PII and prompt injection before sending to LLM
    • ✅ Always validate all LLM-supplied function arguments server-side — never trust them directly
    • ✅ Use Azure AI Content Safety for input/output moderation in production
    • ✅ Enable OpenTelemetry and alert on error rate, latency, and anomalous function-call patterns
    • ✅ Apply least-privilege — give the AI only the permissions the application scenario requires
    • ❌ Don't include secrets, connection strings, or API keys in prompt templates
    • ❌ Don't log full prompts to unencrypted storage — they may contain PII

public class DatabasePlugin
{
    private readonly SqlConnection _db;

    [KernelFunction("get_schema")]
    [Description("Returns the database schema so you can write correct SQL queries")]
    public string GetSchema() => _schemaCache;  // Tables, columns, FK relationships

    [KernelFunction("run_query")]
    [Description("Executes a read-only SQL SELECT query and returns results as JSON")]
    public async Task<string> RunQueryAsync(
        [Description("A safe, read-only SELECT statement")] string sql)
    {
        // Validate: only SELECT allowed
        if (!sql.TrimStart().StartsWith("SELECT", StringComparison.OrdinalIgnoreCase))
            throw new InvalidOperationException("Only SELECT queries are permitted.");
        using var cmd = new SqlCommand(sql, _db);
        var reader = await cmd.ExecuteReaderAsync();
        return await SerializeToJsonAsync(reader);
    }
}
